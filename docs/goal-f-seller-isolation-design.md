## Implemented branch contract

Schema 19 stores businesses, active account memberships, resource ownership, ownership audit, disabled-by-default mode, versioned fee policy/acceptance, sale fee snapshots and provider bindings. Migration 17 stores commerce line/cart/stock snapshots and provider operations; migration 18 corrects only proven equivalent retired default credit shapes. None of these migrations has run on accepted production.

`woodworkers-store.ts` is the ownership and fee authority. A current woodworker role plus active membership, active business and enabled mode are required on each server operation. Primary-business ownership is deterministic; customer emails in projects, inquiries and orders never confer seller ownership. Explicit ambiguous owners remain conflicts. A media path missing from `media_items` is a content-truth problem, not an invented ownership conflict. The administrator resolver requires a provenance reason, records before/after ownership, rejects cross-business relationships and cannot transfer an order with an immutable sale snapshot. Rename/delete triggers and central media-reference rewriting preserve binding and avatar references.

`woodworker-workspace.ts` supplies server-scoped, paginated business, piece, Process, media, project, order, review, inquiry and search data. Quarantined inquiries never enter the seller workspace. `woodworker-actions.ts` checks mutation origin and current authorization before typed mutations. `/studio/woodworker` uses structured fields and the canonical crop editor; `/studio/woodworkers` remains administrator-only and exposes provisioning, activation, mode, fee, Stripe-account binding and auditable ownership decisions. Account navigation takes woodworkers to their scoped workspace. Global Studio remains admin-only.

Uploads begin private under the business folder. Piece selection, ordering, hero/public flags and crop settings persist; reviewed state is separate from ownership and public eligibility. Project attachments cannot become public, a piece photograph or a profile avatar. Blob previews stay in the browser. Server media access returns the same no-store not-found body for another worker's private resource and an unknown path. Customer project access remains separate from seller authorization. Public directories, detail attribution, navigation and sitemap use active/public business truth and remain gated when mode is off.

Checkout derives one seller from verified item ownership, rejects mixed sellers and snapshots an accepted fee version before provider execution. Integer fee arithmetic applies to discounted goods, excluding shipping and tax. Direct-charge Stripe requests and signed events must agree with the immutable order/account binding. EasyPost uses a distinct operator-configured account and origin per seller; retries cannot switch account credentials. Provider timeout, concurrency, replay, changed-rate and database-reopen behavior are covered by focused tests. Authentication mail remains independent of business-recipient routing. Production credentials and actual provider-native sandbox tests remain blocked; see `goal-f-provider-activation.md`.

## Concurrency boundary and transition trigger

Supported here: one application writer using local SQLite, short transactions, atomic reservations and durable provider-operation ownership. No shared SQLite file over SMB, multi-host writer fleet, unbounded marketplace throughput, automatic seller onboarding, or real provider activation is claimed. Before adding application writers, measure transaction wait/busy failures and throughput under representative order/media workloads; move authoritative transactions to a server database such as Postgres or LibSQL, preserving business foreign keys, unique idempotency keys, fee/provider snapshots and audit rows. Re-run competing checkout/label, migration/reopen and cross-tenant acceptance against that database before enabling multiple writers. SQLite's experimental warning alone is not a reason to replace the accepted deployment during Goal F.
